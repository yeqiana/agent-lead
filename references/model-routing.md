# 模型选择与推理强度（运行时策略）

Agent Lead 不绑定 DeepSeek、GLM、Qwen、Codex 或 Claude 的具体版本号。模型目录以当前执行环境提供的能力为准，每次任务可刷新；**不能仅凭模型选择菜单或品牌名称判断它支持原生子 Agent、工具调用或某档推理强度**。

## 能力盘点（只记录核实内容）

| 字段 | 值 | 来源 |
| --- | --- | --- |
| 模型 ID、Provider | 实际枚举/已获确认 | 当前会话、已批准的配置元数据或用户确认 |
| 是否可用于原生子 Agent | yes/no/unknown | 实际工具能力与小规模验证 |
| 可选推理强度 | 具体可用档位/默认/unknown | 模型或客户端明确提供的能力 |
| 是否可调用工具与本地仓库 | yes/no/unknown | 实际执行环境与权限检查 |
| 成本与速度 | 有证据数值/unknown | 已授权监测或可核对记录 |

严禁遍历敏感环境变量、输出 API Token 或对未批准的公网接口作探测。

## 自动选择规则

1. 确认任务是简单、常规、复杂还是高风险；确认成本、时限和数据边界。
2. 从当前**已核实可用**的候选中筛选满足工具能力、权限和上下文需求的模型；没有可靠比较证据时沿用父会话默认模型。
3. 选择本次模型并报告依据；如原生子 Agent 无法指定不同 Provider，不强制跨 Provider，改为获准的独立会话/CLI 或单 Agent。
4. 选择候选推理强度：简单任务 low，常规任务 medium，复杂/高风险任务 high；明确仅为建议，不代表模型一定支持。
5. 对候选强度检查支持集合；`auto` 可选择已确认的最合适档位或保留模型默认值；用户**显式指定**的强度不支持时必须报告，不能假装生效。
6. 如果模型/推理强度在任务中途被修改，只影响确实可重新配置的新任务/会话；不可宣称修改已在运行的调用。

## 用户覆盖示例

```text
$agent-lead 实现用户会话管理模块。模式=multi，并发=2，推理强度=auto。
```

```text
$agent-lead 评审缓存一致性方案。模型=auto，推理强度=high，评审=on。
```

```text
$agent-lead 实现接口测试。主控模型=auto，开发模型=<当前可用模型ID>，开发推理强度=medium。
```

## 失败与降级结果

- `unsupported_model`：目标 ID 不在当前已核实候选中，保留原模型；要求用户另选或使用 auto。
- `unsupported_effort`：模型/客户端不支持指定强度，不能静默降档；如用户选 auto，可使用默认强度并说明。
- `provider_isolation`：不同 Provider 不能由当前原生子 Agent 统一路由，改为独立会话或单 Agent。
- `subagent_unavailable`：原生子 Agent 不可用，降级为单 Agent 并明确报告。
- `permission_denied`：缺少目录/网络/外部工具权限，不尝试绕过。

> 各客户端、Provider 的支持能力会变化。Skill 是协作策略，不是可用模型列表的权威来源。
