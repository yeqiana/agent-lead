# Agent Lead

**定位**：负责协作决策的 Skill，不是新的模型网关、MCP、调度服务或自动化守护进程。除非运行环境明确提供对应工具，不能宣称已经启动子 Agent、切换模型或调节推理强度。

## 1. 接受任务与覆盖参数

默认接受自然语言需求，可附加以下可选设置；没有指定时使用 `auto`：

- `模式=auto|single|multi`：简单任务优先单 Agent。
- `模型=auto|<当前可用模型ID>`：可单独指定 `主控模型`、`开发模型`、`评审模型`；实际能否分别指定，以执行环境能力为准。
- `推理强度=auto|none|minimal|low|medium|high|xhigh|max`：只使用**当前模型实际支持**的档位；可按角色覆盖，如 `评审推理强度=high`。
- `并发=auto|1|2|3`：默认上限 3，运行时实际允许更少时以实际能力为准。
- `评审=auto|on|off`、`外部CLI=off|approve`：默认不自动调用独立 CLI。

**优先级**：当前用户明确指定 > 当前项目规则与安全限制 > 已验证的运行时能力 > 任务自动推荐 > 父会话默认设置。用户设置也不能突破平台或组织权限。

## 2. 运行前做最小能力确认

1. 阅读当前仓库 `AGENTS.md`、已有协作规则和任务验收要求；不覆盖公司/用户的模型配置、Provider、凭据或全局设定。
2. 仅使用当前会话可见的模型菜单、可信本地配置元数据、工具提供的能力列表或用户确认的清单，确定本次**实际可用**的模型与可配置推理档位。禁止读取或打印密钥、擅自请求第三方模型 API 或以模型品牌猜测能力。
3. 记录 `模型ID / Provider / 执行方式 / 可用推理强度 / 证据来源`。未核实的字段标记 `unknown`；模型增删后，在下一次任务重新评估，不维护写死的固定型号表。
4. 区分三种执行方式：原生子 Agent、独立 Codex 会话及 Worktree、显式获准的外部 CLI。Skill 不能自行把不同 Provider 的模型变成同一原生子 Agent 池。
5. 无法确认模型能力时使用**已能正常执行的父会话配置**，并明确说明；不能伪造模型切换、降级或并发记录。

详见 [模型与推理策略](references/model-routing.md)。

## 3. 决定是否分工

- **single**：单文件、低风险、无需独立审查或可直接验证的任务。
- **multi**：跨模块、有独立分析或审查价值、任务边界清晰且并行收益大于沟通/调用成本的任务。
- **串行优先**：需求尚不清晰、接口未定、多个工作项必须依次修改同一资源时，先确定契约再并行。
- 不为凑 Agent 数量而拆分；先给出任务依赖、责任人/子 Agent、文件归属、输入输出和验收证据。

## 4. 模型与推理强度分配

1. 对本次**已验证可用**的模型做任务匹配，考虑代码能力、上下文、工具支持、实际成本和历史验证效果，**不按厂商品牌写死“架构/开发/评审”岗位**。
2. `auto` 的初始建议：简单检索 `low`，常规实现/测试 `medium`，复杂架构、并发根因和安全评审 `high`；这只是**候选强度**，由实际支持集合和预算约束决定能否应用。
3. 用户指定模型或强度时，优先尝试精确设置并确认结果；若不支持，不得静默改为另一个强度或模型。报告 `unsupported` 并说明可用备选，由用户决定或显式使用 `auto`。
4. 不支持可调推理强度的模型，使用其默认推理设置，并报告 `fixed/default`；不将提示词“认真思考”包装成 API 的推理档位切换。
5. 尽可能用不同的可用模型交叉评审，但不能为此绕过 Provider 限制或引入外部数据传输。

## 5. 执行与隔离

- 优先使用执行环境已支持的**原生子 Agent**；若不可用，使用单 Agent 或明确标识为“独立会话/手动交接”，不得伪称已经并发。
- 只读分析可并行；代码修改须分配互不重叠的文件/模块范围。真正并行修改同一 Git 仓库时，使用独立 Worktree/分支，并明确合并负责人。
- 代码修改与测试有依赖关系时，最终集成测试必须发生在**同一个最终提交或工作树快照**上。
- 外部 CLI（如 Claude CLI）仅在安装可用、组织授权并得到用户批准时调用；默认只读；不要开放它自行递归启动更多 Agent。
- 不安装 MCP、新网关、后台服务或额外框架；不擅自提交、推送、发布或执行破坏性命令。

## 6. 交付与验收

最终报告要简短但可追溯：

- **模式**：single/multi、实际启动的 Agent 数、是否真正并行。
- **模型**：实际使用的模型和 Provider、推理强度；无法验证处标 `未核实`。
- **变更**：修改文件与边界、集成版本；与计划的偏差。
- **验证**：运行过的命令、退出码、测试结果；未执行的验证明确写出。
- **结果**：完成/部分完成/阻断，遗留风险、是否需要人工审批。

不可把“Agent 说完成了”当作验收证据。遇到无法执行的能力，展示限制和可用的最小替代路径。
